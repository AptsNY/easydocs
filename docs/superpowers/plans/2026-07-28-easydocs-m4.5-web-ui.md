# easydocs M4.5 — Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the spec §9 React SPA — all eight screens (dashboard, document console with the Actions menu and members panel, comparison/redline view, Major Versions tab, copies management, approvals, public share landing, settings) — plus the backend read surface those screens need and that M0–M4 never built. Exit gate: a non-technical user can complete the whole document lifecycle in a browser without touching an HTTP client, and `npx playwright test` proves it against the real stack.

**Architecture:** Two phases, in order. **Phase A (Tasks 1–8)** closes the read-surface gaps found in the pre-execution audit: the existing list endpoints return too little to render §9, and approvals/org/trash have no GET at all. Phase A is pure ASP.NET Core + xUnit, TDD as usual. **Phase B (Tasks 9–18)** builds the SPA against that surface. Frontend testing is **Playwright only** — no Vitest, no React Testing Library: one test tool that drives the real app against the real API, which simultaneously closes spec §12.3's "headless-browser driver" gap that M0–M4 substituted away.

**Tech Stack:** ASP.NET Core 10 minimal APIs + EF Core (existing). React 19 + Vite 8 (existing). **New dependencies, three total:** `react-router` (8 screens need real routing), `@playwright/test` (E2E + the §12.3 browser driver). No state library — SSE already gives us cache invalidation, which is the entire reason it exists. No UI component library, no Tailwind: plain CSS extending the existing `web/src/index.css`, with the visual pass driven by the `frontend-design` skill in Task 17 as spec §9 prescribes.

**Spec:** `docs/superpowers/specs/2026-07-24-easydocs-v1-design.md` — §9 (web UI, the eight screens, the indented-branch-list `ponytail` ceiling), §10 (auth + the `resolve_role` chokepoint), §10.1 (endpoint set), §10.2 (SSE + the cookie-vs-`?token=` rule), §11 (security), §12.1 (E3 "list shows author/time/summary", E8 "Actions menu present and functional", E12 role matrix), §12.3 (headless-browser driver).

**Builds on:** M0–M4 (main @ `faf375b`). 55 mapped routes, E1–E12 green with zero skips in CI. `Program.cs:168-173` already serves the SPA (`UseDefaultFiles` → `UseStaticFiles` → `MapFallbackToFile("index.html")`), and `Program.cs:86-95` already falls back to the `ed_session` cookie for JWT auth, so browser `EventSource` authenticates without new work.

## Pre-Execution Audit — findings that shaped this plan

This plan exists because the M5 plan never mentions the SPA and `web/src` is a 140-LOC health-check stub. Before writing it, spec §9 was audited against the real code. **Nine gaps**, all confirmed by reading the endpoints, not by trusting a checkbox:

| # | Gap | Evidence | Fixed in |
|---|---|---|---|
| A | Version list DTO is `{id,major,minor,revision,source,createdAt,createdBy}` — no `name`, no change summary, no publish state, no `parentVersionId`, **no branch fields** | `DocumentEndpoints.cs:234-238` | Tasks 1–3 |
| B | Document list DTO is `{id,name,folderId}` — no version number, no last-modified, no author | `DocumentEndpoints.cs:133` | Task 4 |
| C | No trash listing — `ListDocuments` filters `DeletedAt == null` with no `?trashed=` escape | `DocumentEndpoints.cs:125` | Task 4 |
| D | **Approvals are write-only** — zero GET endpoints anywhere | `ApprovalEndpoints.cs:21-23` | Task 5 |
| E | No org endpoints — no member list, no standalone invite (invitations only mint as a side effect of `POST /documents/{id}/members`) | `MemberEndpoints.cs:88-102` | Task 6 |
| F | No user directory — `createdBy`, `approverId`, `requestedBy`, audit `ActorUserId` all render as raw GUIDs; an author removed from the document is unresolvable | `DocumentEndpoints.cs:236`, `AuditEndpoints` | Tasks 3, 6 |
| G | `/s/{token}` returns JSON and `/s/{**rest}` hard-404s — an external recipient sees raw JSON | `ShareEndpoints.cs:126`, `Program.cs:172` | Task 7 |
| H | Both list endpoints hardcode `descending: false` — history renders oldest-first, "latest" needs paging to the end | `DocumentEndpoints.cs:130,233` | Task 1 |
| I | `vite.config.ts` has no `server.proxy` — `npm run dev` cannot reach the API at all | `web/vite.config.ts` (7 lines) | Task 9 |

**Plus one real defect the audit turned up that is not a §9 gap at all** — `POST /versions/{vid}/approvals` never validates that the named approvers are document members (`ApprovalEndpoints.cs:37-45`), and `Respond` authorizes on `ar.ApproverId == me` alone (`ApprovalEndpoints.cs:65`). So today you can name a non-member as approver, and that non-member **can record an approval decision on a document they cannot read**. Fixed in Task 5, Steps 1–4, with its own regression test. This is an E12 role-matrix hole, not cosmetic.

### Deliberate spec deviations this plan makes — both need to stay visible in the PR description

1. **§10.1 is described as "authoritative", and this plan adds endpoints to it** (`GET /approvals`, `GET /versions/{vid}/approvals`, `GET /documents?trashed=true`, `GET /api/v1/org`, `GET/POST /api/v1/org/members`, `PATCH/DELETE /api/v1/org/members/{uid}`). §9 cannot be built without them: a write-only approvals API cannot render an approvals screen. Task 8 updates §10.1 in the spec so the document and the code stop disagreeing.
2. **Branch topology moves onto the v1 public surface.** M0–M4 deliberately kept it off (`ConformanceFixture.cs:12-14` documents conformance reading the DB to verify branch closure). But §9 requires "main branch with grouped *concurrent branch* entries + a Merge button", which is unrenderable without `branchId`/`branchKind` on the version row. Task 1 exposes them. The DB-reading conformance deviation stays as-is — it is still the stricter test.

### Non-gaps confirmed, so nobody re-investigates them

- `POST /versions/{vid}/sessions` already returns a ready-to-iframe `editorUrl` (`EditingEndpoints.cs:50-62`). The Collabora screen is an `<iframe src>`, nothing more.
- SSE already accepts the `ed_session` cookie (`Program.cs:86-95`), so `new EventSource('/api/v1/documents/{id}/events')` works with no `?token=` plumbing.
- `GET /folders?parentId=` lists one level at a time (`FolderEndpoints.cs:26-32`). That is exactly right for a lazily-expanding tree — do not add a whole-tree endpoint.
- `DELETE /folders/{id}?mode=` already implements promote-vs-trash (`EdApi.DeleteFolderRawAsync`, `ConformanceFixture.cs:96`).
- Login/register already set the `httpOnly` `ed_session` cookie (`AuthEndpoints.cs:68-74, 97-103`), so the SPA needs no token storage. **Note the cookie is `Secure = true`:** browsers treat `http://localhost` as a secure context so local dev works, but a self-hoster serving plain HTTP on a LAN IP will silently fail to log in. Task 18 documents this in the README; do not "fix" it by dropping `Secure`.

## Conventions for every task

- **TDD, and verify the failure reason.** Write the test, run it, read the error. If it fails because of a typo or a missing `using` rather than the behaviour under test, fix that first. A test that fails for the wrong reason proves nothing.
- **Backend:** `export PATH="$PATH:$HOME/.dotnet/tools"` for `dotnet ef`. `dotnet build easydocs.slnx` must emit **0 warnings** (`TreatWarningsAsErrors`). Baseline before you start: **234 passed, 2 skipped** (both PDF — no local `soffice`; CI installs it and skips 0).
- **Frontend:** `npm --prefix web run build` (tsc strict + vite) and `npm --prefix web run lint` (oxlint) must both pass before every commit.
- **`DocxFixtures.Base()` rebuilds the zip on each call** — zip entries carry timestamps, so two calls are *not* byte-identical. Capture bytes in a variable before comparing.
- **Fix at the chokepoint, not per caller.** `VersionListProjection` and `DocumentListProjection` exist so one enrichment serves every consumer.
- **Deliberate cuts get a `ponytail:` comment** naming the ceiling and the upgrade path (spec Appendix). There are 6 in `src/` today.
- **Never assert success without running the command.** Quote real output in the commit body when a task's result is non-obvious.

```csharp
using EasyDocs.Api.Data;
using EasyDocs.Api.Domain;
using Microsoft.EntityFrameworkCore;

namespace EasyDocs.Api.Versioning;

// One console row (spec §9). Built with a FIXED number of queries no matter the page size: the
// dashboard and console are the two hottest reads in the product, and a per-row query here would be
// an N+1 the moment a document has real history.
public sealed record ChangeSummary(int Insertions, int Deletions, int Moves, int FormatChanges);

public sealed record VersionListRow(
    Guid Id, int Major, int Minor, int Revision, string Number, string? Name, string Source,
    string? PublishedKind, DateTimeOffset? PublishedAt, string? PublishName, bool HasPdf,
    Guid? ParentVersionId, Guid BranchId, string BranchKind, int BranchOrdinal,
    Guid? BranchMergedIntoVersionId, Guid CreatedBy, string CreatedByName,
    DateTimeOffset CreatedAt, ChangeSummary? Summary);

public static class VersionListProjection
{
    public static async Task<List<VersionListRow>> BuildAsync(
        EasyDocsDbContext db, IReadOnlyList<DocumentVersion> versions, CancellationToken ct)
    {
        if (versions.Count == 0) return [];

        var branchIds = versions.Select(v => v.BranchId).Distinct().ToArray();
        var branches = await db.Branches
            .Where(b => branchIds.Contains(b.Id))
            .ToDictionaryAsync(b => b.Id, ct);

        var authorIds = versions.Select(v => v.CreatedBy).Distinct().ToArray();
        var authors = await db.Users
            .Where(u => authorIds.Contains(u.Id))
            .Select(u => new { u.Id, u.DisplayName })
            .ToDictionaryAsync(u => u.Id, u => u.DisplayName, ct);

        var summaries = await SummariesAsync(db, versions, ct);

        return versions.Select(v =>
        {
            var b = branches[v.BranchId];
            return new VersionListRow(
                v.Id, v.Major, v.Minor, v.Revision, $"{v.Major}.{v.Minor}.{v.Revision}",
                v.Name, v.Source.ToString(), v.PublishedKind, v.PublishedAt, v.PublishName,
                v.PdfBlobSha256 is not null, v.ParentVersionId,
                b.Id, b.Kind.ToString(), b.Ordinal, b.MergedIntoVersionId,
                // An author removed from the document is still a User row, so the name resolves.
                // A hard-deleted user would not — fall back rather than throw on a history read.
                v.CreatedBy, authors.GetValueOrDefault(v.CreatedBy, "(unknown)"),
                v.CreatedAt, summaries.GetValueOrDefault(v.Id));
        }).ToList();
    }

    // Per-row summary = the cached parent->child diff. Null when DiffSummaryWorker has not drained the
    // job yet; the console shows a dash and refreshes on the `diff.ready` SSE event.
    private static async Task<Dictionary<Guid, ChangeSummary>> SummariesAsync(
        EasyDocsDbContext db, IReadOnlyList<DocumentVersion> versions, CancellationToken ct)
    {
        var parentIds = versions
            .Where(v => v.ParentVersionId is not null)
            .Select(v => v.ParentVersionId!.Value)
            .Distinct()
            .ToArray();
        if (parentIds.Length == 0) return [];

        var parentSha = await db.Versions
            .Where(v => parentIds.Contains(v.Id))
            .Select(v => new { v.Id, v.BlobSha256 })
            .ToDictionaryAsync(v => v.Id, v => v.BlobSha256, ct);

        var wanted = versions
            .Where(v => v.ParentVersionId is { } p && parentSha.ContainsKey(p))
            .Select(v => (VersionId: v.Id, From: parentSha[v.ParentVersionId!.Value], To: v.BlobSha256))
            .ToList();
        if (wanted.Count == 0) return [];

        // Fetches a superset (the two IN lists cross-multiply) and is then indexed by the exact tuple.
        // ponytail: a superset scan over one document's diffs, not a tuple-IN. Push the pairs into a
        // VALUES join if a document ever has enough versions for this to show up in a profile.
        var froms = wanted.Select(w => w.From).Distinct().ToArray();
        var tos = wanted.Select(w => w.To).Distinct().ToArray();
        var rows = await db.VersionDiffs
            .Where(d => froms.Contains(d.FromSha256) && tos.Contains(d.ToSha256) && d.Insertions != null)
            .ToListAsync(ct);
        var byPair = rows.ToDictionary(d => (d.FromSha256, d.ToSha256));

        var result = new Dictionary<Guid, ChangeSummary>();
        foreach (var w in wanted)
            if (byPair.TryGetValue((w.From, w.To), out var d))
                result[w.VersionId] = new ChangeSummary(
                    d.Insertions!.Value, d.Deletions ?? 0, d.Moves ?? 0, d.FormatChanges ?? 0);
        return result;
    }
}
```

```csharp
    private static async Task<IResult> ListDocuments(
        HttpContext ctx, EasyDocsDbContext db, Guid? folderId, string? q, string? cursor, int? limit, bool? trashed)
    {
        var orgId = CurrentUser.OrgId(ctx.User);
        var userId = CurrentUser.UserId(ctx.User);

        var wantTrash = trashed is true;
        var query = db.Documents.Where(d => d.OrgId == orgId
            && (wantTrash ? d.DeletedAt != null : d.DeletedAt == null)
            && db.DocumentMembers.Any(m => m.DocumentId == d.Id && m.UserId == userId));
        if (folderId is { } fid) query = query.Where(d => d.FolderId == fid);
        if (!string.IsNullOrWhiteSpace(q)) query = query.Where(d => EF.Functions.ILike(d.Name, $"%{q}%"));

        var page = await Pagination.PageAsync(query, cursor, limit, descending: false, ctx.RequestAborted);
        return Results.Ok(new
        {
            items = await DocumentListProjection.BuildAsync(db, page.Items, ctx.RequestAborted),
            nextCursor = page.NextCursor,
        });
    }
```

```ts
// One fetch wrapper for the whole SPA. `credentials: 'same-origin'` carries the httpOnly ed_session
// cookie; RFC-7807 problem+json bodies (§10) become a typed ApiError so screens can show `detail`
// instead of "something went wrong".
export class ApiError extends Error {
  constructor(
    readonly status: number,
    readonly title: string,
    readonly detail: string,
  ) {
    super(detail || title)
  }
}

async function request<T>(method: string, path: string, body?: unknown): Promise<T> {
  const res = await fetch(path, {
    method,
    credentials: 'same-origin',
    headers: {
      Accept: 'application/json',
      ...(body === undefined || body instanceof FormData ? {} : { 'Content-Type': 'application/json' }),
    },
    body: body instanceof FormData ? body : body === undefined ? undefined : JSON.stringify(body),
  })

  if (!res.ok) {
    const problem = await res.json().catch(() => null)
    throw new ApiError(res.status, problem?.title ?? res.statusText, problem?.detail ?? '')
  }
  return res.status === 204 ? (undefined as T) : ((await res.json()) as T)
}
```

```ts
import { useEffect } from 'react'

// The 7 v1 event types (spec §10.2). EventSource cannot send an Authorization header, which is
// exactly why Program.cs falls back to the ed_session cookie — so this needs no token plumbing.
export type DocEvent =
  | 'version.created' | 'version.published' | 'merge.completed' | 'diff.ready'
  | 'member.added' | 'push.requested' | 'approval.responded'

export function useSse(documentId: string | undefined, onEvent: (e: DocEvent) => void) {
  useEffect(() => {
    if (!documentId) return
    const es = new EventSource(`/api/v1/documents/${documentId}/events`)
    const types: DocEvent[] = [
      'version.created', 'version.published', 'merge.completed', 'diff.ready',
      'member.added', 'push.requested', 'approval.responded',
    ]
    // ponytail: every event triggers the same re-fetch — no per-event patching of local state. The
    // payloads are small and the reads are cheap; diff the payload only if a profile complains.
    for (const t of types) es.addEventListener(t, () => onEvent(t))
    return () => es.close()
  }, [documentId, onEvent])
}
```

Callers must pass a stable `onEvent` (`useCallback`) or the stream reconnects on every render — note that in the hook's doc comment, and assert it in the test by counting `EventSource` constructions if it proves flaky.

## Deviations from this plan, and unplanned work

Same reason M3 and M4 recorded theirs: the audit is the part worth keeping. This plan's own
Pre-Execution Audit is why Phase A existed at all, and the pattern repeated inside execution — most of
what follows is the plan being wrong about the code, found by running things rather than by trusting the
plan.

### The two deliberate spec deviations (both stand, both in the PR description)

1. **Endpoints were added beyond §10.1, which the spec calls "authoritative."** `GET /approvals`,
   `GET /versions/{vid}/approvals`, `GET /documents?trashed=true`, `GET/PATCH /api/v1/org`,
   `GET/POST /api/v1/org/members`, `PATCH/DELETE /api/v1/org/members/{uid}`. §9 is unbuildable without
   them — a write-only approvals API cannot render an approvals screen, and there was no way to list a
   trashed document, so trashing one made it unrecoverable unless you had kept its GUID. Task 8 updated
   §10.1 so the spec and the code stop disagreeing.
2. **Branch topology moved onto the public v1 surface.** M0–M4 kept it off deliberately. But §9 requires
   grouped concurrent-branch entries with a Merge button, which cannot be rendered without `branchId`,
   `branchKind`, `branchOrdinal` and `branchMergedIntoVersionId` on the version row. The conformance
   suite still reads the database to verify branch closure — that is the stricter test, so it stays.

### Six unplanned bug fixes, all pre-existing except one

Every one was found by this milestone and fixed in it, because each blocked or falsified a §9 screen.
Four were defects in already-shipped code.

3. **Approvals privilege escalation** (`4793d45`) — the audit found it, and Task 5 Step 1 proved it by
   *succeeding* where it should have 400'd. `POST /versions/{vid}/approvals` never checked that the named
   approvers were document members, and `:respond` authorized on `ApproverId` alone, so a same-org
   non-member could record a decision on a document they could not read. An E12 role-matrix hole. Both
   ends fixed, so rows written by the vulnerable build cannot be decided either.
4. **Concurrent identical uploads returned 500** (`e94d234`) — `CommitSaveAsync` did check-then-insert on
   `Blobs`, whose PK is the sha256, with no unique-violation guard. Two people uploading the same
   attachment at once is ordinary, and it made the parallel Playwright suite flaky on a cold database,
   which is how it surfaced. Fixed at the one write path, so upload, import, WOPI save, merge, revert and
   copy-push are all covered.
5. **`member.added` was never published** (`f44a6bb`) — §10.2 listed it as a v1 SSE event; nothing emitted
   it, so an open console never learned about a roster change. Task 12's spec had a `page.reload()`
   workaround in it, which is the tell; the reload was deleted in `3638c11` once the event was real. The
   reconciliation ran both ways: the code also published **four events §10.2 never listed** —
   `pdf.ready`, `push.reviewed`, `version.named`, `version.reverted` — so the spec's "7 v1 event types"
   was wrong in both directions, and the hook now subscribes to the real set.
6. **Error bodies were not RFC 7807** (`e3725cb`) — a body-binding failure already returned 400, but with
   an empty body in Production and, in Development, a leaked exception dump as `text/plain`. Handled once
   ahead of auth so it covers every endpoint, narrowed to `BadHttpRequestException` so a genuine fault
   still 500s.
7. **Any non-UTC `DateTimeOffset` returned 500** (`5d706c6`) — Npgsql's `timestamptz` mapping accepts only
   offset 0, so a conforming client sending `+02:00` on `dueAt` or `expiresAt` — valid RFC 3339, and
   advertised as `date-time` in the OpenAPI document — got a bare 500. One `JsonConverter<DateTimeOffset>`
   in `ConfigureHttpJsonOptions` normalizes at deserialization, covering all three affected fields and any
   future one. A bare date is read as midnight **UTC**, not the server's local midnight, so the same
   request cannot resolve to different instants on different hosts.
8. **`/s/{token}` was cacheable, and the shell replayed over the JSON** (`de46163`) — found in Task 18,
   by the very act of pointing Playwright at the shipped container instead of Vite. One URL, two
   representations: the `text/html` branch is `Results.File` over `wwwroot/index.html`, so it carries
   `Last-Modified` and no `Cache-Control`; Chromium heuristically cached it and then served the cached
   shell to the SPA's `Accept: application/json` fetch of the same URL (identical `Content-Length` and
   `Date` in the trace). `res.json()` threw, and **every live share link rendered "This link is no longer
   available."** Vite's dev server sends `no-cache` on `index.html`, which is why 23 commits of green dev
   runs never reproduced it. `Vary: Accept` is the correct answer for a negotiated URL; `no-store` is
   correct independently, because this GET increments `ViewCount` and writes `share_link.viewed`, and a
   cached response silently loses both. **This is the whole argument for Task 18 Step 1 in one bug: under
   Vite the suite was green and the shipped artefact was broken.**

### Where the plan was simply wrong about the code

9. **Task 10 has no standalone deliverable.** SSE is document-scoped, so the hook has no consumer until a
   document screen exists — its own Step 1 test needs a console to count rows in. `useSse.ts` and
   `sse.spec.ts` shipped inside Task 12's commit (`5560882`). "Build it before the screens so every screen
   gets invalidation for free" was the right instinct about the design and the wrong instinct about the
   commit boundary.
10. **The `/s` Vite proxy could not be a string prefix.** Vite matches proxy keys as prefixes, so `'/s'`
    also captures `/src/main.tsx` — which breaks the dev server outright — and the client-side
    `/settings` route. Hence the two regexes in `vite.config.ts`, plus a `bypass` that serves Vite's own
    `index.html` for a `text/html` share navigation so dev gets HMR instead of a stale `wwwroot` build.
11. **`erasableSyntaxOnly` bans constructor parameter properties.** `ApiError` assigns its fields in the
    body rather than in the signature. Noted in `api.ts` so nobody "tidies" it back and breaks `tsc`.
12. **The planned polling loop was replaced by a deterministic synchronous diff.** Task 2 as written
    polled for `DiffSummaryWorker` to drain its in-memory `Channel`. `compare?format=summary` computes
    inline and upserts `version_diffs` before responding, so the test forces the diff instead of racing
    the worker. A poll loop in CI is a flake waiting to happen. The Task 1 review also caught that
    `SummariesAsync` had no coverage at all — it could have `return []`d unconditionally and Task 1's
    tests would still have passed.
13. **E9 through the UI needed a genuinely external reviewer.** The plan said "forks a copy, then pushes
    back and a push request appears for review." But the copy's *creator* holds a role on the parent, so
    their push is `auto_accepted` and no pending request is ever created — there would have been nothing
    to review. `copies.spec.ts` invites a second user as Editor of the copy only, which is both the real
    E9 shape (an outside counsel returning a redline) and the only shape that produces a pending request.
14. **Task 16b's diagnosis was wrong.** The malformed-JSON ticket assumed a 500; probing showed the
    framework already returned 400 — the defect was the *body* (see 6). The real 500 was a separate,
    unreported bug the investigation walked into: non-UTC offsets (see 7). Two fixes, not the one the
    ticket described.
15. **No README screenshots.** Task 18 Step 3 asked for "a screenshot or two." Skipped: committing PNGs
    of a UI that is still pre-release buys a stale-screenshot problem nobody has yet, and the rule was to
    only link images that actually exist. Reconsider at M5, when the UI stops moving. In their place the
    README carries an explicit **not-built-yet** list — no OIDC/SSO, no desktop Word, no rate limiting, no
    DAG graph, no content search — since the honest half of a status section is the half that says what is
    missing.
16. **Writing the README turned up a gap nothing else had: share-link revocation is unreachable.**
    `DELETE /api/v1/share-links/{id}` exists and works, but `POST /versions/{vid}/share-links` returns only
    `{token, url}` — the row's id is never exposed — and **nothing lists share links**, so no client can
    reach the route. `copies.spec.ts`/`share.spec.ts` had already noted this in a `ponytail:` comment while
    testing an *expired* link instead, and E10 proves "revocable" only by reading the id straight out of
    the database (`E10_ShareDownload.ShareLinkIdAsync`) — the same DB-reading deviation branch topology
    used to need. So the criterion is honest about the data model and silent about client reachability.
    **Not fixed here** — it is a new read endpoint, i.e. a tenth read-surface gap, and inventing scope at
    Task 18 is how a milestone stops closing. Recorded in the README's not-built-yet list, with "set an
    expiry" as the working answer, and it belongs in M5's security pass.
17. **Task 17 shipped as two commits, not one** (`f26908f` share landing, `adcd7a5` design + a11y). The
    design pass touched every route; keeping it separate from the new screen keeps the diff reviewable.
